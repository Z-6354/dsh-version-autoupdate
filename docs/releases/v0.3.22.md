# v0.3.22

This release fixes update-state corruption on repeated requests and prevents global updates from targeting a different DSH installation.

- Verify the package manager's global directory against the running DSH package before installing; recognize desktop, npx and source installations and restrict unsupported operations.
- Dispose HTTP routes and the floating capsule with their Cordis context; require the correct HTTP methods and reject restart requests during updates.
- Follow the DSH Node range `^22.19.0 || >=24.0.0`, improve SemVer validation and build-metadata comparison, and honor `DSH_HOME` for logs and offline state.
- Remove the legacy client-runtime dependency and add client type checking. Rebuild before packing, include complete declarations and source exports, and emit a separate source map to reduce the client script from about 102 KB to 18 KB.
- Update configuration documentation, synchronize the lockfile, and remove deployment-specific trusted origins from the shipped template.

Validation: client type checking, build, and 42 tests pass; npm package contents checked. Installation tests use simulated subprocesses.

Compatibility is based on DSH `0.2.0-rc.2` and `0.2.1-alpha.1` source contracts. Live DSH validation, the native desktop updates bridge, alpha reverse-proxy path-prefix support, and successful process-restart handoff remain unverified or unimplemented. Preview still selects the highest published version, including alpha/rc.
